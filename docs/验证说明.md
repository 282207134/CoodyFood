## 手动体验路径

1. 打开 App，浏览三页引导，或点击 **Skip**。
2. 登录页可选择 **Explore as a guest**；也可用格式正确的邮箱和至少 8 位密码演示登录。
3. 首页选择 **Pizza**，进入 **Domino’s**，点击商品，选择芝士加料并加入购物车。
4. 点击 **View Order**，调整数量后进入 **Go to Checkout**。
5. 在下方输入 `COODY40` 并点击 **Apply**，检查总额联动；备注会随订单快照保存。
6. 选择演示付款方式，提交订单，点击 **Track Order**。
7. 在订单页向下滚动，点击 **Mark as delivered**，进入历史订单后完成三步评价。
8. 在 **Profile** 中修改资料、地址和通知偏好，关闭并重新打开应用检查本地恢复。

也可体验餐厅收藏、菜单分类、评论切换、列表/网格切换、搜索无结果、位置选择、卡片添加和邀请码复制。

## 素材和代码整理

- 运行时只有 `flutter_svg`、`shared_preferences` 两个额外依赖。
- 使用原稿 DM Sans 三种字重。照片提取后转换为 WebP、限制最大尺寸，三张引导插画保留矢量路径。
- 公用表单页、餐厅卡片、导航、弹层内容、购物车数量控件和金额计算复用；未为每张设计稿复制独立状态逻辑。
- 截图示例状态放在 `test/fixtures.dart`，不进入应用运行时代码。
- 原始 Sketch 大文件和临时解析 JSON 不留在项目中；保留导入工具、图片索引及 Pixso 页面映射，便于追溯。

## 实现边界

- **账号**：表单和流程演示，没有服务器认证。社交登录显示接入说明；验证码固定为 `1234`。重置密码不会修改任何真实账号。
- **支付**：没有交易请求。卡片表单执行格式和有效期校验，只保存品牌及末四位；不保存完整卡号、CVC 或密码。扫码页提供手动录入入口，不启用相机。
- **地图**：使用原稿静态地图，标记可点击；没有真实 GPS、导航或地图服务。
- **订单**：只持久化当前演示订单快照；历史列表包含设计稿示例卡片。配送时间线为演示，点击送达按钮推动状态。
- **通知**：页面数据和设置保存在本地，不请求系统推送权限。
- **邀请**：提供邀请码复制，不向第三方发送消息。
- **平台**：Android 构建和模拟器测试已执行；iOS 需 macOS 签名与后续验证。Web 代码共用 Flutter 页面。
- **视觉**：使用原始素材和主要布局层级还原；Flutter 系统图标、圆角、字号细节和系统安全区有平台适配。原稿部分超长页面通过滚动呈现。

此项目适合 UI 验收、演示和继续接入业务接口。正式上线还需要服务端、真实授权流程、支付令牌化、配送数据、可审计订单存储、正式签名及目标设备回归验证。
